# Arius.Api — agent contract

## Layout
Vertical slices, mirroring `Arius.Core` ([ADR-0027](../../docs/decisions/adr-0027-api-vertical-slices.md)); namespaces mirror folders (`Arius.Api.Features.<Area>`, `Arius.Api.Shared.<Area>`).
- `AriusApiHost.cs` — composition root (`AddAriusApi()` / `MapAriusApi()`; `Program.cs` only calls them). Everything app-level is a singleton; the `IHostedService`s are `SchedulerService`, `RehydrationPollingService`, `StaleApprovalSweepService` and `DownloadCleanupService`. REST under `/api`, hub at `/hubs/arius`, Angular SPA from `wwwroot` with a fallback to `index.html`.
- `Features/<Area>/` — one folder per area (Health, Accounts, Repositories, Defaults, Snapshots, Statistics, Browse, Jobs, Schedules, Archive, Restore, Downloads, Cost, Filesystem): one file per endpoint named after it (`CreateAccount.cs`: an `internal static class` with `Map(IEndpointRouteBuilder)`) plus `<Endpoint>Dtos.cs` for its request/response records; a DTO shared within the area gets its own file (`AccountDto.cs`). Areas with several REST endpoints keep an `<Area>Endpoints.cs` that owns the route group and area-local helpers. Hub methods are feature files too (`Features/Archive/StartArchive.cs`, a static `HandleAsync`). Background services and Core-event forwarders sit in their area (`Features/Restore/RehydrationPollingService.cs`, `Features/Archive/ArchiveForwarders.cs`, `Features/Schedules/SchedulerService.cs`, `Features/Downloads/DownloadCleaner.cs`).
- `Shared/` — what two or more areas need: `AppData/` (`AppDatabase`, partial files per table; `Records.cs`; `OptionDefaults`, the four-level defaults hierarchy — resolve through it, never re-implement precedence; `SecretProtector`), `Composition/` (`RepositoryProviderRegistry`, `IRepositoryCoreComposer`), `Jobs/` (`JobRunner`, `JobSink`, `JobStateRegistry`, `RestoreApprovalRegistry`, `JobFormat`, ...), `Downloads/` (`DownloadStaging`), `Hubs/JobsHub.cs` (a pure dispatcher), `Hosting/`. A download is a restore into staging, not a second code path: change `RunRestoreJobAsync`, not a copy.
- Rule of thumb: a type lives in its feature area until a second area needs it, then it moves to `Shared/` (or is marked `[SharedWithinAssembly]` if it must stay put). Features never depend on each other, `Shared` never depends on `Features`, and the Api reaches Core only through `IMediator` — `ApiArchitectureTests` enforces all three (it cannot see inside `async IAsyncEnumerable` bodies — the hub streaming features — so review those). Map Core types to DTOs in the feature (`Features/Browse/EntryMapping.cs`); never expose Core records directly.

### Adding an endpoint or hub method
- **REST endpoint:** add `Features/<Area>/<Endpoint>.cs` (`internal static class <Endpoint>` with `Map(...)`) and, if it has request/response records, `<Endpoint>Dtos.cs`; register it in the area's `<Area>Endpoints.cs`, or — for an area with a single endpoint (e.g. `GetStatistics`) — in `AriusApiHost.MapAriusApi()`. A new area gets its own folder and namespace.
- **Hub method:** add the feature file with a static `HandleAsync` taking its dependencies as parameters, then a one-line forwarding method in `Shared/Hubs/JobsHub.cs`. Keep logic out of the hub. Hub method names are wire contract with the SPA.
- **Forwarded Core event:** add an `INotificationHandler<T>` in `Features/Archive/` or `Features/Restore/`; it is picked up automatically.

## Project-local idioms & gotchas
- **Three provider kinds** (`RepositoryProviderRegistry`). *Read providers* are cached per repo (`PreflightMode.ReadOnly`), warm caches across requests, and get an inert `JobSink()`. *Job providers* are built fresh per archive/restore, owned and disposed by the job. After an archive (or a properties change / delete) call `Evict(repositoryId)` — the read cache's chunk index is single-shot after flush, so it must be rebuilt. A *repository-less provider* (`GetRepositoryLessProvider()`, built once, owned by the registry — never dispose it) serves Core requests that need no repository, e.g. `ContainerNamesQuery` for the account's container picker (`IRepositoryCoreComposer.ComposeWithoutRepository` → Core's `AddAriusWithoutRepository()`).
- **Per-job event isolation is by provider, not a correlation id.** Each job provider registers its own `JobSink` singleton; the auto-registered `INotificationHandler<T>` forwarders resolve *that job's* sink. Don't add a jobId filter to the forwarders.
- **`AddMediator()` must be called in `BuildAsync`**, not inside `AddArius` — the Mediator source generator runs against *this* assembly, so it must register the forwarders living here.
- **`JobRunner` serializes writers per repo** via a `SemaphoreSlim` keyed by repositoryId — two mutating jobs never share a repo's on-disk state. Restore's `ConfirmRehydration` callback streams a `CostEstimate` then awaits `RestoreApprovalRegistry`; a prompt abandoned for 24h is declined by `StaleApprovalSweepService` (deliberately not tied to the SignalR connection).
- **`JobSink` is the only client channel**: `Log`/`Progress`/`CostEstimate`/`Done` to the job's SignalR group. It also holds the aggregate counters (`Interlocked`) feeding the drawer's stat grid.
- **App SQLite (`AppDatabase`: accounts/repos/jobs/download_files/schedules/global_defaults/repository_defaults/statistics_cache/app_settings) is separate from Core's chunk-index cache.** Raw `SqliteConnection` + WAL + parameterized commands, mirroring Core's local-store idiom.
- **Secrets at rest**: account keys and passphrases go through `SecretProtector` (ASP.NET Data Protection, key ring on the mounted volume) — *not* Core's passphrase content encryption. Never store plaintext keys; always `Protect`/`Unprotect`.

## Run & test
- Run: `dotnet run --project src/Arius.Api` (dev state under `.appstate/`; CORS allows `http://localhost:4200` for `ng serve`). In Development only, the OpenAPI doc is at `/openapi/v1.json` and the Scalar UI at `/scalar` (wired in `AriusApiHost`, gated on `IsDevelopment()`; nothing registers in Production).
- Tests: `src/Arius.Api.Tests` (unit), `src/Arius.Api.Integration.Tests` (in-process host with scripted Core scenarios from `src/Arius.Api.FakeTestHost`), and the ArchUnit rules in `src/Arius.Architecture.Tests` (`ApiArchitectureTests` for this project). The two test projects mirror the `Features/` / `Shared/` tree. Build the host after any Core contract change — see the root contract's testing section.
